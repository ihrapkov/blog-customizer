# План реализации панели настройки статьи

| Шаг                                     | Что делаем                                                                                                                                                                                                                                                                                                           | Где хранится состояние                                                                                                                      | Как происходит взаимодействие                                                                                                         |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Организовать композицию**          | • На странице блога (`ArticlePage` / `src/pages/...`) добавляем кнопку‑стрелку `<SidebarToggle />`. <br>• Компонент `<Sidebar>` (или `<ArticleParamsSidebar>`) будет обёрнут в `<Drawer>`‑похожий контейнер, который открывается слева/справа. <br>• Внутри `<Sidebar>` рендерится готовый `<ArticleParamsForm />`.  | Состояние открытия/закрытия боковой панели хранится в родительском компоненте страницы (например, в `useState<boolean>(false)`).            | `<SidebarToggle onClick={…}>` меняет этот `boolean`. Боковая панель получает проп `open={…}` и `onClose={…}`.                         |
| **2. Хранение текущих параметров**      | • При первом рендере страницы читаем текущие CSS‑переменные из `document.documentElement.style.getPropertyValue('--var')`. <br>• Эти значения сохраняем в локальное состояние `initialParams`. <br>• Параметры, которые пользователь меняет в форме, находятся в отдельном состоянии `draftParams`.                  | `initialParams` – `useRef` (чтобы не терять исходные значения при закрытии/открытии). <br>`draftParams` – `useState` в `ArticleParamsForm`. | При монтировании `ArticleParamsForm` получаем `initialParams` через проп `defaultValues`. Все изменения записываются в `draftParams`. |
| **3. Применение изменений**             | • Кнопка **«Применить»** в форме вызывает колбэк `onApply`. <br>• `onApply` перебирает `draftParams` и устанавливает CSS‑переменные через `document.documentElement.style.setProperty('--var', value)`. <br>• После применения обновляем `initialParams` (чтобы «Сбросить» возвращал именно новые текущие значения). | `initialParams` обновляется внутри `onApply`.                                                                                               | Родительская страница передаёт `onApply` в форму. После применения форма закрывается (optional).                                      |
| **4. Сброс настроек**                   | • Кнопка **«Сбросить»** вызывает `onReset`. <br>• `onReset` копирует `initialParams` обратно в `draftParams` и сразу же применяет их (как в пункте 3).                                                                                                                                                               | `initialParams` остаются неизменными, `draftParams` сбрасывается.                                                                           | `onReset` вызывается из формы, передаётся из родителя.                                                                                |
| **5. Открытие/закрытие боковой панели** | • При клике на кнопку‑стрелку меняем `isSidebarOpen`. <br>• При открытии сохраняем текущие CSS‑переменные в `initialParams` (если они могут измениться извне). <br>• При клике «вне» боковой панели или повторном нажатии‑стрелке вызываем `onClose`, который просто меняет `isSidebarOpen = false`.                 |
| **6. Типы и валидация**                 | • Описать тип `ArticleParams` (например, `{fontSize: string; lineHeight: string; …}`) в `src/types.ts`. <br>• В `ArticleParamsForm` использовать `react-hook-form` или обычные controlled‑inputs с типизацией.                                                                                                       |
| **7. Тестирование**                     | • Написать unit‑тесты для `ArticleParamsForm` (проверка, что при `apply` вызывается `onApply` с правильными данными). <br>• Интеграционный тест: открытие/закрытие боковой панели, клик «вне» закрывает её.                                                                                                          |
| **8. Финальная проверка**               | • Убедиться, что стили действительно меняются (можно добавить небольшую storybook‑страницу). <br>• Проверить, что при повторном открытии панель показывает актуальные значения (из `initialParams`).                                                                                                                 |

**Краткая последовательность действий**

1. **Page component** – добавить состояние `isSidebarOpen`, `initialParamsRef`.
2. **SidebarToggle** – переключать `isSidebarOpen`.
3. **Sidebar** – принять `open`, `onClose`, отрисовать оверлей + `<ArticleParamsForm>`.
4. **ArticleParamsForm** –
   - пропсы: `defaultValues`, `onApply`, `onReset`, `onClose`.
   - `useState` `draftParams`.
   - Кнопки «Применить» / «Сбросить».
5. **onApply** / `onReset` – работа с CSS‑переменными.
6. **Обработчик клика вне** – навесить на оверлей или слушать `mousedown`/`click`.

После согласования плана можно приступить к реализации — начать с изменения родительского компонента страницы, затем добавить `<Sidebar>` и доработать `<ArticleParamsForm>`.
